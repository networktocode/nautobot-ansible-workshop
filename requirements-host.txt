# Lockfile for the host's Python venv at /opt/ansible, used to run the
# playbooks and the awx CLI from the shell. Attendees do not need it.
#
#   /opt/ansible/bin/pip install -r requirements-host.txt
#
# The venv is bootstrapped from six packages by name:
#
#   ansible-core pynautobot awxkit invoke toml paramiko
#
# The rest are transitive dependencies, pinned so that the environment is
# reproducible instead of being resolved afresh on each install.
#
# setuptools is deliberately pinned below 81. setuptools >= 81 no longer ships
# pkg_resources, and awxkit 24.6.1 imports it at the top of its CLI, so the
# `awx` command fails immediately with:
#
#   ModuleNotFoundError: No module named 'pkg_resources'
#
# Keep the pin until an awxkit release drops that import.
#
# This is not the execution environment's dependency list. The EE names its
# Python packages in ee/execution-environment.yml and takes collections from
# collections/requirements.yml. The two resolve independently, so a transitive
# package such as cryptography can differ between the host and AWX. The file
# is not named requirements.txt so that tooling which treats a root
# requirements.txt as the EE's Python list does not pick it up.
#
# To update after a deliberate bump, rebuild the venv from the six packages
# above and regenerate, then restore this header:
#
#   /opt/ansible/bin/pip freeze > requirements-host.txt
#
# Python 3.12 on Ubuntu 24.04 LTS. Resolves to prebuilt wheels on both amd64
# and arm64.
